- **评估对象**: 老板 2026-08-11 三条指令（React 重构/TS strict 并行友好/现代简洁不平铺）、主会话技术计划 `/home/jiayu/.claude/plans/mutable-nibbling-music.md`、前端现状 `internal/webui/web/`（5 页 HTML + app.js 2703 行 + style.css 1016 行 + vendored lightweight-charts v4.2.3）、2026-08-02 UI Goal（富途/IB/嘉信交互参照 + 主题化）

## 一、需求栈确认（React 重构是否值得）

**结论：值得，且时机正确。** 依据（读现状核实，非推断）：

1. **单体 JS 已达复杂度拐点**：app.js 2703 行单文件全局脚本，约 90 个函数 + 30+ 隐式全局状态（如 `wheelSignalItems`/`wheelConfigItems` 模块级变量、detailSymbol/detailAdjust 记忆），5 页共享一份脚本，页面初始化靠 DOM 存在性守卫。近两周新增能力（datacheck、wheel 信号审计、配置版本深链、一键回测跳转）都叠加在同一文件上——**每加一个功能都要改全站共享文件**，这正是老板「为后续更复杂前端」的痛点。
2. **「减少代码」需诚实表述**：手绘 canvas（drawSparkline/drawEquityCurve/drawMultiCurve/drawCurvePlot/renderCandlestickChart，约 300 行）+ 自写 makeTableSorter/renderTable/轮询/主题 ≈ 1500 行会被 antd + lightweight-charts + 3 个 hook 替代；但 TSX 模板本身有增量。**净效果是代码量不必然下降（2703 → 预计 3500–4500 行结构化 TSX），下降的是单功能复杂度与并行冲突成本**。验收应看「每页独立目录 + 共享层冻结 + 新功能接入成本」，不看总行数。
3. **并行派发是真实收益**：现状单文件 5 页互锁，任何两个 UI 任务不能同时开工；React 化后页面目录零重叠（主会话 D1/D5 已论证），这是老板三条指令里工程价值最高的一条。
4. **产品面现状已不错**：空态文案、错误条、忙态按钮、hover/touch 读数、sticky 表头、数字右对齐等 2026-08-02 以来沉淀的交互是资产，**React 化必须等价保留，不是推倒重来**。

### 验收预期（老板可感知的「现代简洁不平铺」，可核对清单）

**原则：每页一个主任务，第一屏无滚动可见主任务；次级功能以 Tabs/抽屉/折叠收纳；状态色与主题跨页一致。**

| 页 | 主任务 | 现代布局方向 | 收纳手段 |
| --- | --- | --- | --- |
| Dashboard | 账户总览（资产 + 持仓） | 指标卡行（Statistic 五卡）→ 资产曲线主图 → 持仓主表 | 订单/最近入库收进 Tabs |
| Watchlist | 观察标的监控（策略页） | 观察列表主表 + 能力状态语义色 | 复杂 WheelForm 编辑抽屉化（Drawer，宽 640 自适应锚点行）；信号审计/配置版本 Tabs 分层 |
| Results | 回测结果浏览与对比 | 结果列表（分页）+ 详情视图（指标卡 + 权益曲线主图 + Tabs：交易/信号轨迹/参数） | 启动回测表单抽屉化；详情抽屉或独立视图；对比独立 Tabs |
| Data | 数据完整性与行情浏览 | datacheck 汇总卡为视觉主角 + 覆盖主表 | 期权新鲜度与覆盖表 Tabs；行情明细右侧面板（现布局已接近现代，保留双栏强化） |
| Admin | 集群健康 + 配置管理 | 集群 4 卡（Card + 状态徽标） | 配置 / Telegram 向导 Tabs；向导 Steps 化 |

**可核对验收项（每项均可肉眼或 grep 判定）**：
1. 5 页顶部导航 active 高亮；主题切换全站同位置，浅色 + 两套深色 × 5 页视觉一致（antd token 派生，禁新硬编码色）
2. 每页第一屏即见主任务（无滚动）；至少一处 Tabs/抽屉/折叠实际生效，收起状态主任务完整可用
3. 状态色语义跨页一致：READY 绿 / DATA_BLOCKED 黄 / ALERT 橙 / HOLD 灰（现有 token 沿用）
4. 空态引导文案逐表保留（如「暂无历史快照；可运行 wbot ingest account 开始记录」）；加载态（Spin/骨架屏）；错误态 = 错误条 + 可重试动作（ApiError 的 message · action 契约）
5. 深链逐条手测：`#bt-<id>`、`#signal-<id>`、`#config-<symbol>-v<N>`、一键回测跳转（watchlist → results#bt-）
6. 数字列右对齐 + tabular-nums（已沉淀 #82）；长表限高 sticky 表头（已沉淀 #81）
7. 767px 窄屏响应式行为与现有一致（style.css:906 已实现，不得退化）
8. 红线 grep：任何 bundle 无 `/v1/futu/quote`；admin 配置值不回显；零外链（BotFather 外链豁免）
9. 刷新/轮询行为保留：30s 自动刷新 + visibilitychange 暂停 + 「更新于 HH:MM:SS」+ 刷新忙态按钮
10. 功能等价对照清单落盘（见下「切片建议」S0 交付物），逐项核对，不留口头「应该可以」

## 二、信息架构建议（不平铺的具体手段）

参考富途/IB 的账户总览、策略面板、回测报告布局（对照 2026-08-02 UI Goal）：
- **Dashboard 照富途账户总览**：资产数字是视觉主角（大号 Statistic + 涨跌色），曲线紧随其后，持仓/订单降为次级表。现状的「摘要 + 曲线 + 三张表纵向堆叠」正是「平铺」典型——主会话建议的 Tabs 收纳正确。
- **Watchlist 照富途自选列表**：列表为主、编辑为浮层。WheelForm 有曲线编辑器 + 9 个数字参数，是全站最重的表单，抽屉化收益最大；但锚点行在窄抽屉不可用，抽屉宽度须自适应（≥640px 或宽度走查）。
- **Results 照富途/IB 回测报告**：指标卡行 + 大曲线 + 明细表三段式；启动表单收纳；详情深链直达。注意**对比选择必须跨分页保留**（搜索结果分页后多选状态提升到页面级，翻页丢选是产品级 bug）。
- **Data**：datacheck 是近期新能力（本分支刚交付），必须出现在 P3 且保持汇总卡 + 明细表形态；行情明细右侧面板已是「主任务 + 次级」结构，保留强化。
- **Admin**：配置只写不读与 Telegram 向导的「步骤感」用 Steps/Tabs 表达，避免三个区块并列。

## 三、切片建议（产品版，与主会话对照）

### 切片 0「基线」（与主会话同构，关键路径单飞，2–3 人天）

脚手架 + doc/FRONTEND.md + 共享层（api/hooks/lib/components）+ 参考页 dashboard 全量迁移 + 构建链 + 测试迁移矩阵。**产品视角增补三件交付物**：
1. **「功能等价对照清单」落盘 doc/tasks 或 FRONTEND.md 附录**：按 5 页盘点现状功能（我按当前 html/app.js 实读盘点约 70 项：Dashboard 12 项、Watchlist 18 项、Results 17 项、Data 13 项、Admin 8 项、全站 6 项），P1–P4 每片以清单逐项核对为验收根基——主会话「对照旧功能清单逐项等价」只有口头表述，须实体化。
2. **占位页中间态声明**：切片 0 合入后 P1–P4 未全合入前，4 页为「迁移中」占位（功能不可达）。此窗口是已知中间态，须写入切片 0 任务记录与验收（HTTP 200 只证明壳在，不等于功能可用），并约束主会话合入节奏。
3. **dist 体积基线记录**：每页 JS bundle 目标 < 800KB（antd 5 按 import tree-shaking，无需 babel-plugin）；切片 0 记录首值，超限在切片 5 前处理（manualChunks/懒加载），避免「现代简洁」被加载白屏拖累。

### 切片 S1–S4「页面并行」（与主会话 P1–P4 同内容，每片 0.5–1 人天）

内容一致（S1 watchlist / S2 results / S3 data / S4 admin），仅两点补充：
- **合入顺序建议 watchlist → data → results → admin**（不是编码顺序，是主会话逐片合入的顺序）：策略监控与数据完整性是日常高频页，让中间态窗口内最重要的两页最先恢复完整功能；results 依赖 WheelForm 契约（S0 已冻结，无先后约束）；admin 最独立可最后。
- **空/加载/错误态按上表验收项 4 逐页核对**：现状空态文案是全的，React 化最容易丢的就是「旧空态文案」，每片验收清单必须含空态逐表核对。

### 切片 5「收尾」（与主会话同构，0.5–1 人天）

删占位、红线 grep、主题走查、深链 e2e、体积记录、文档。**产品视角增补**：
- 主题视觉走查清单化：5 页 × 3 主题 × 关键组件（Table 斑马纹/排序图标、Tag 语义色、Statistic、Drawer、Tabs、表单校验错误色、图表轴色/网格线）逐项过，不留「整体看看」（对应主会话 R3 风险）。
- 深链 e2e 从「冒烟」升级为逐深链手测清单（验收项 5）。
- 验收脚本复跑：现有 accept-*.sh（14 个脚本、~140 项检查）全部是 HTTP/CLI 契约、不依赖 UI，重构后应全绿不变——这是「重构零破坏」的强校验，切片 5 必须在 dist 之上连跑一遍（dev-up 冒烟 + accept 抽查）。

**总工作量约 6.5–8 人天，墙钟 4–5 天（切片 0 → 4 路并行 → 收尾），与主会话估算一致。**

## 五、风险与反对意见（产品视角，对主会话计划的异议与补充）

1. **权益曲线「逐点浏览」取舍（对 R7 的反对）**：主会话将「箭头键逐点浏览 → crosshair + OHLC legend」记为行为等价取舍。产品上这是**可感知退化**：逐点浏览是已实现的键盘可达性（a11y）能力，hover/touch 读数由 crosshair 替代可接受，但键盘逐点浏览不应静默移除。建议：保留 tabindex + aria（轻量包装，在 crosshair 上做键盘移动），或至少作为 P2 增补列入 backlog 并在验收清单显式记录「已移除、老板知情」。不拦主重构。
2. **bundle 体积（R6 的量化）**：MPA 每页重复打包 antd 是产品感知问题（首屏白屏时长）。建议量化目标 < 800KB/页并切片 0 记录基线，而非「记录为已知项」了事。
3. **占位页中间态（补充约束）**：切片 0 → P1–P4 之间最多 2–4 天窗口 4 页不可用。可接受，但必须显式声明（见切片建议 0.2），合入顺序按高频页优先，避免「合入 0 后长期停留中间态」。
4. **对比选择跨分页丢失**（P2 细节）：搜索+分页替代加载更多后，results 对比多选必须页面级保留。主会话计划未提，补充。
5. **antd 与金融语义融合（R3 深化）**：antd 默认蓝主色/白底与现有 token（金融语义色）融合风险真实存在。走查清单化 + ConfigProvider token 运行时派生已在主会话计划，同意；补充「表格斑马纹/选中色/排序图标」进走查清单。
6. **测试迁移分工**（同意主会话）：Go 保留契约断言（标题/304/404/红线 grep），实现细节断言交 vitest——分工正确；唯一提醒：Go 侧「dist 产物 grep」依赖构建产物，CI 顺序（frontend job → artifact → test job）必须一次跑通，否则 go build 在无 dist 时编译失败（R2）会成为 CI 首个红色，阻碍全组合入——切片 0 内先建 dist 再切 embed 的顺序敏感点正确，执行时勿乱序。
7. **「减少代码」的验收口径**：总行数不必然下降（2703 → 3500–4500 TSX），验收口径应放在「每页独立目录 + 共享层冻结 + 新功能接入成本 + 并行度」，避免执行时被「行数增加 = 失败」误导。这是产品侧对老板指令的预期管理。
