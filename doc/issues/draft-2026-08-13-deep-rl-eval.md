# 战术参数整体替换为深度强化学习的产品评估（sol，2026-08-13）

## 评估结论与裁决边界

“状态 → 是否出手及卖哪个合约”是策略级强化学习问题，长期方向成立；但以当前数据和模拟器条件，**不能训练出可证明可靠、可替代现有战术规则的深度策略**。当前 `READY` 的只是按 bar 选取最新原子快照、在 bar close 机械结算的研究回放；历史逐 quote/成交事件、完整盘口/Greeks 覆盖、到期/指派时序与人工处置事实仍是 `DATA_BLOCKED`。在这个环境中提高模型容量，只会提高拟合缺失模式和利用模拟器缺陷的能力，不会提高真实决策可信度。

这也不等于否定深度 RL。建议保留“策略级模型最终替换人工战术阈值”的目标，但当前产品路线采用 **ES 先行、深度模型并轨预研**：先用 ES 完成数据面、回测契约、成交模型、walk-forward 和轨迹沉淀；同时定义 RL 状态/动作/日志 schema，并用 ES/现有 Wheel 轨迹做行为克隆预热。只有历史事件数据与模拟器闸门通过后，才允许离线 RL 参与 shadow 对比。

“战术参数消失”必须准确解释：`move_interval_pct`、`min_premium_per_share`、`stock_switch_pct`、`trade_gap`、`min_option_quality`、`min_dte/max_dte` 不再作为用户可调、ES 可搜索的决策阈值；但以下约束不能交给模型学习，也不能随字段一起消失：数据完整性与新鲜度、允许的合约/到期宇宙、现金担保、备兑、最大库存、战略状态、待成交互斥、禁止裸 Call、交易成本下限和异常行情停机。它们应成为版本化产品政策与 action mask，而不是伪装成另一组“可优化参数”。战略价格—库存曲线和最大库存继续由人定义。

## 1. 当前数据可行性

### 1.1 现有数据能支持什么

仓库现有快照 schema 已具备训练状态所需的基础列：underlying price、期权类型、行权价、到期日、Delta、bid/ask、IV、Theta、volume、OI、lot size、`observed_at` 和原子 `snapshot_key`。Wheel trace 也保存动作、阻断原因、快照身份和库存分解。这些是未来建设训练集的正确地基。

但现状只足以做以下工作：

- 验证状态编码、action mask、奖励计算和可复现性；
- 用 deterministic fixture 做端到端训练 smoke test；
- 用现有 Wheel 或 ES 候选生成行为克隆样本；
- 在 `RESEARCH_ONLY` 下比较算法是否能复现基线，而不能证明收益能力。

不能据此宣称模型学会了真实的出手时机或合约选择，因为当前回放在每根 bar 读取截至该时点的最新快照，并在 bar close 机械成交/结算；它缺少订单在盘口中的生命周期、部分成交、撤单、quote 变化顺序、真实滑点、指派及人工是否执行等决定 reward 的事实。

### 1.2 为什么“bar 数很多”仍不等于样本够

深度离线 RL 需要的是有覆盖的**状态—动作—后果转移**，不是重复且高度相关的行情行数。Wheel 的收益延迟到平仓、到期或指派，5–10 DTE 的相邻 bar 大量共享同一市场状态；把它们都计为独立样本会严重夸大有效样本量。当前还存在四类覆盖风险：

1. **动作覆盖不足**：历史策略没有选择过的合约/时机没有可信反事实收益，离线模型会对分布外动作产生虚高估值。`HOLD` 又很可能占绝大多数，导致策略塌缩为永不出手，或通过重采样后反向过度交易。
2. **市场覆盖不足**：单一标的、短时间窗口或单一波动区间不能覆盖上涨、下跌、震荡、波动率跃迁、流动性枯竭、除权和临近到期等状态。
3. **执行覆盖不足**：启发式未成交概率不是成交标签；如果真实 fill/撤单/部分成交数据缺失，模型会把模拟假设当市场规律。
4. **尾部覆盖不足**：最大回撤、Put 指派和 Call 机会成本由少数路径主导。普通时期的大量快照不能替代足量的尾部 episode。

因此当前不能给出“已有 N 条即可训练”的结论；仓库文档没有提供一份通过质量验收的训练数据 census，能力状态本身仍为 `DATA_BLOCKED`。后续进入深度训练前，至少应由数据报告证明：

- 每个标的按交易日/时段/DTE/方向/流动性/波动率分桶的原子快照覆盖率、缺失率和最大时间间隔；
- 覆盖多个完整市场阶段，而不是把同一段行情切成大量相关 bar。实践入口可先以每标的连续 24–36 个月、包含显著涨跌/震荡和高低波动阶段为采集目标，但是否足够必须由有效 episode 与分桶覆盖判断；
- 对候选动作有真实或可信可校准的 bid/ask 后续路径、成交/未成交、到期/指派结果；仅有日线或单点 snapshot 不合格；
- 训练池达到至少 `10^5` 量级的有效决策转移、关键动作/状态桶有足够支持后再讨论小型深度网络。该数值只是启动实验的量级门槛，不是可靠性保证；若只有日频数百到数千步，应停止在规则/ES/表格模型；
- 最近一段连续时间及至少一个完整市场阶段永久封存为测试集，任何特征、奖励、超参和 action mask 调整都不得查看其结果。

跨标的合并可以增加样本，但必须对价格、库存、合约乘数和波动率归一化，并保留 symbol/market regime；否则只是把不同市场微观结构混成更大的偏差。样本量达标也不能解除事件数据和模拟器真实性闸门。

## 2. 建议架构

### 2.1 状态空间

状态必须是某个决策时点可获得的、带有效时间的结构化快照，不允许使用未来 bar、到期结果或事后修订字段。建议拆成四组：

| 状态组 | 首版特征 | 估计维度 |
| --- | --- | ---: |
| 标的/市场 | 相对战略区间位置，短中期收益与实现波动，振幅，成交量，时段/交易日，数据 freshness | 12–24 |
| 账户/库存 | 现金及担保占比，实际/有效/目标库存及归一化 gap，现有 Put/Call Delta、到期分布、未实现损益、战略状态 | 15–30 |
| 执行/历史 | 上次建议与成交后的价格变化、距上次动作时间、当日尝试/成交、pending order、近期 fill/slippage、连续 HOLD/阻断 | 10–20 |
| 单个候选合约 | put/call、moneyness、DTE、Delta、bid/ask、相对价差、IV、Theta、volume、OI、lot、权利金收益率、交易后/指派后库存 | 14–22/合约 |

全局向量约 40–70 维。若每侧保留 top 8–16 个候选，候选张量为 16–32 × 14–22；直接摊平约 250–700 维，且合约增删会改变位置语义，因此不建议把它当固定宽度普通向量。

首版应使用“全局 MLP + 共享候选 MLP encoder + masked pooling/attention + 每候选 score head”：共享 encoder 保持候选置换等价，模型输出每个候选的分数和一个独立 HOLD 分数。若要利用最近若干决策时点，可先加入固定长度 8–32 步的摘要或 GRU；在数据覆盖不足时不要直接上大型 Transformer。Transformer 更适合候选较多、时序较长且已有大量多标的数据，当前只会增加参数量、泄漏面和审计成本。

### 2.2 动作空间与 action mask

推荐离散动作：

```text
HOLD
SELL_PUT(candidate_i, quantity_bucket)
SELL_CALL(candidate_i, quantity_bucket)
STOCK_ADJUST_BUY(quantity_bucket)
STOCK_ADJUST_SELL(quantity_bucket)
```

若正股调整仍只作为建议，可保留两个动作；若产品未准备好定义其成交/成本/审核语义，首版先移出动作空间，避免把不等价动作混入同一 reward。数量先用 1 张或少量离散桶，不做连续动作；候选数量 K 固定，不足补 mask，超过 K 必须用不含未来信息的确定性预筛选。

action mask 在网络打分前由 Wheel 领域层计算，并永久拦截：

- 不完整、过期、倒挂、零流动性、市场/币种/乘数不一致的快照；
- Put 现金担保不足、指派后超过最大库存；
- Call 无备兑、会形成裸仓或与战略状态冲突；
- 动作使有效库存更偏离目标、存在 confirmed-but-unfilled 同标的动作或重复合约；
- 处于 `DATA_BLOCKED`、停牌/闭市/异常时钟、人工暂停状态；
- 不在产品批准的合约和到期宇宙内。

模型只能在 mask 后的合法动作中排序，不能把违规写成负 reward 让模型“自己学会”。`HOLD` 永远合法。日志必须同时保存未 mask 原始分数、mask 原因、最终概率/价值、模型版本和输入快照哈希，便于审计模型是否长期偏好被风控拒绝的动作。

### 2.3 奖励

奖励应以组合净清算权益变化为基础，而不是单笔毛权利金：

```text
r_t = Δnet_liquidation_value
      - fees - slippage - taxes
      - λ_dd × incremental_drawdown
      - λ_tail × tail_exposure_change
      - λ_turn × unnecessary_turnover
```

所有项按初始净值或风险预算归一化并版本化。到期、指派、股票变化和未成交必须改变后续状态；未成交已通过没有建立仓位和实际成本反映，不应再机械重复扣罚。奖励需要注意：

- 只按收到权利金给正奖会诱导卖最近/最危险合约；
- 只用逐 bar mark-to-market 会受 stale quote 和 bid/ask 标记方式影响；
- 最大回撤是路径量，建议使用增量回撤惩罚并在 episode 末报告完整最大回撤，不把同一损失重复惩罚；
- 硬约束违规不进入 reward 比较，直接 mask；若模拟器仍产生违规，整条 episode 标记无效并报警；
- reward 权重必须在训练前冻结，测试集上不得调权重；同时报告未经合成的收益、回撤、成本、换手、指派和机会成本，防止单一 score 掩盖退化。

episode 至少覆盖一次完整持仓生命周期；在 5–10 DTE 场景中按自然周随意截断会错误分配尾部收益。训练还应使用不同成交模型/费用/滑点压力场景，避免只对一套启发式最优。

### 2.4 算法与 Go 工程现实

PPO 是 on-policy 算法，需要反复与可信环境交互。当前只能在 bar-time 机械模拟器中 rollout，PPO 会高效利用该模拟器的固定成交与结算漏洞，样本效率又低，因此不适合作为首个算法。普通 DQN 虽适配离散动作和 replay buffer，但在离线数据上会高估历史分布外动作；candidate action 数量动态变化、延迟奖励和 action mask 也会显著增加实现与验证难度。

Go 纯手写一个“能跑”的 MLP/DQN不难，难的是训练系统的正确性与可审计性：自动微分/优化器、masked batch、序列 replay、target network、checkpoint、恢复、数值稳定、确定性 seed、指标、模型 schema、数据版本、离线评估和跨版本推理一致性。纯 Go 自研 DQN/PPO 应按新的训练平台看待，而不是 ES 的数百行扩展；没有成熟训练运行时和基准对拍时，隐藏错误风险高于算法收益。技术栈固定 Go 时建议：

1. Go 继续拥有模拟器、特征/轨迹生成、硬风控、评估、模型注册和线上推理；
2. 首个模型只做小型候选 encoder + 行为克隆/排序，先证明数据管道、mask 和模型回放一致；
3. 真正离线 RL 优先选择保守价值估计思路，限制在行为数据支持的动作附近；若坚持纯 Go，先实现离散 masked Double-DQN 基线并与穷举小环境对拍，不直接实现 PPO；
4. 训练框架通过梯度检查、固定小 MDP、checkpoint round-trip、同 seed 可复现及 Go race/资源上限后，才可消费真实数据。

样本效率由高到低大致是：监督行为克隆/候选排序 > ES 搜索 7 个全局阈值 > 保守离线 RL > 在现有模拟器中从零 PPO。行为克隆只复现老师，不能证明超过 ES；它的价值是预热表示、验证 action mask 和降低早期随机探索。

## 3. 深度策略与 ES 参数寻优对比

| 维度 | ES 战术参数寻优 | 深度状态→动作策略 |
| --- | --- | --- |
| 收益上限 | 受固定规则与 7 个阈值限制，不能细分每个市场状态；上限较低但边界清晰 | 理论上能学习非线性时机、候选交互和 regime 条件，收益上限更高 |
| 当前可信度 | 可在有限数据上做低维稳健平台研究；仍因事件数据缺失只能 `RESEARCH_ONLY` | 当前不能可靠训练；容量越大越容易利用 bar-time 和成交启发式 |
| 样本效率 | 高；每次回测直接比较一组全局参数，搜索维度低 | 低；需要大量有动作覆盖的转移和完整延迟结果，状态高度相关 |
| 过拟合 | 参数边界、撞边界、多窗口稳定性较容易观察 | 模型、特征、reward、候选预筛选四重选择偏差；分布外动作估值难发现 |
| 工程成本 | Go 零依赖实现小，现有计划和报告 schema 可直接承载 | 新增训练平台、特征库、模型注册/推理、离线评估、漂移监控和回滚；量级显著更高 |
| 上线周期 | 数据面完成后是周级研究能力，仍需样本外闸门 | 在数据解锁之后仍是月级平台建设与 shadow 观察；当前无法给可靠上线日期 |
| 可解释性 | 可展示每个阈值、触发规则和参数敏感性 | 只能给动作概率/价值、局部特征贡献、近邻案例；不能提供等价于规则的因果解释 |
| 审计/回滚 | 参数 JSON + 代码版本即可较完整复现 | 必须额外保存模型/特征/reward/训练数据哈希、mask、原始输出、校准与漂移状态 |
| 失效方式 | 通常表现为某些行情阈值不合适，较容易限制 | 可能在罕见状态突然选择训练分布外合约，且高置信度不代表正确 |

深度模型可以适配现有链条，但职责应是：

```text
可信状态 → RL 排序并提议 → Wheel 硬风控/action mask → LLM 审核 → 人工决定
```

LLM 能检查结构化矛盾、新闻/上下文风险并生成人类可读摘要，但不能为神经网络提供形式化正确性证明，也不能把模型不可解释性“审核掉”。LLM 只允许批准、拒绝或降级为 HOLD，不得放宽 mask、改数量或把低置信动作升级。人工看到的至少包括：候选与备选、预计净收益/风险分解、模型置信度及校准桶、与当前规则/ES 的分歧、mask 排除项、数据新鲜度和相似历史样本；不能只显示一句模型理由。

## 4. 分阶段路线

### 阶段 A：ES 先行并把数据面做成 RL-ready

按既有 S0–S7 推进 ES，但现在就冻结共用的版本化轨迹：决策前状态、完整候选集、每项 mask 及原因、被选动作、模拟/真实 fill、下一状态、reward 原子分项、终止原因、配置/数据/代码/成交模型版本。ES 报告继续作为低维、可解释基线。此阶段不因未来 RL 而跳过未成交模型、事件回测或样本外验证；这些恰恰是 RL 的前置条件。

### 阶段 B：行为克隆/排序预热

用现有 Wheel 与多组 ES 稳健候选作为 teacher，对合法候选训练 `HOLD + candidate ranking` 小模型。训练目标是：在未见时间窗复现老师、mask 后违规率为零、概率校准可用、Go 推理和离线批量推理逐样本一致。应保留多个 ES/规则老师及其 score，避免只克隆一个偶然冠军。

这一步可验证模型工程，但不能作为替代 ES 的收益证据。ES 轨迹来自同一模拟器，行为克隆只会继承其盲点；“ES 预热 + PPO”也不会凭空产生真实反事实结果。

### 阶段 C：事件数据解锁后的保守离线 RL

数据与模拟器闸门通过后，在行为克隆权重上做保守离线 RL；训练动作限制在行为数据支持范围，和 `现行规则`、`ES 稳健平台`、`仅行为克隆`、`始终 HOLD` 四个基线比较。采用 anchored walk-forward、多 seed、多成交/费用压力场景和跨标的留一验证。任何测试窗口用于调参后即失去测试资格，必须换新的封存窗口。

### 阶段 D：shadow mode 与有限替换

RL 与生产确定性策略同时读取同一快照，但 RL 不驱动提醒、不写配置、不下单。shadow 日志记录两者分歧以及后续可观测结果。只有连续多个预先规定的观察窗口满足下列条件，才可让 RL 替换“战术提议”一层：零硬约束违规、DATA_BLOCKED 时 100% HOLD、样本外净收益/回撤达到预注册门槛、未成交与换手不劣化、置信度校准稳定、分歧样本人工评审通过。替换后仍经过 Wheel、LLM 和人工，且可一键回退确定性策略。

不建议“直接深度 RL”。也不建议为了形式上的混合而同时用 ES 优化神经网络权重：维度过高，样本效率和可诊断性都会丧失。合理混合是 **ES 提供稳定老师/基线与数据轨迹，行为克隆预热，事件数据解锁后再做保守离线 RL**。

## 5. 风险与发布闸门

### 5.1 数据泄漏

- 所有特征按 `event_time <= decision_time` 构建，并同时保留 source/observed/ingested time；不能仅按数据库写入时间排序。
- 标准化、缺失值统计、候选 top-K 阈值、特征筛选和 reward 权重只在训练窗拟合。
- 同一到期周期和重叠持仓生命周期不能随机拆到 train/test；采用时间隔离并设置 purge/embargo，防止相邻 bar 和未结束仓位跨窗。
- 公司行动、合约退市和幸存者偏差必须按当时可见 universe 重建；不得使用今天仍可查询的合约列表回填历史。
- 每份模型保存数据 manifest/hash，并运行自动 future-read audit；发现一次未来读即整份报告作废。

### 5.2 模拟器缺陷利用

- 禁止同 bar 观察 close 后又按该 close 成交；决策时间、订单提交时间和可成交 quote 必须严格分离。
- 未成交、部分成交、撤单、bid/ask、费用、税费、停牌、公司行动、提前行权/指派和到期必须有明确版本语义。
- 建立 adversarial fixtures：零价差/极宽价差、stale quote、断层、极端 IV、跨日、除权、到期边界、现金恰好不足、已有 pending order。
- 对成交率、滑点、延迟和指派模型做压力矩阵；只在单一模型上胜出的策略不得晋级。
- 监控异常获利模式，如总在 bar 边界成交、集中选择缺失字段合约、收益主要来自一次机械结算；触发即阻断而非用 LLM解释。

### 5.3 样本外与统计闸门

- 预注册数据切分、指标、奖励和晋级标准；train/valid/test 时间顺序，最终测试一次性使用。
- 至少 5 个训练 seed，并报告样本外中位数、P10/P90、最差窗口、最大回撤、尾部损失、换手、成交率和硬约束违规数。
- 与规则/ES 在完全相同的候选 universe、成本、成交 seed 和资金约束下配对比较；不能让 RL 获得更多数据或更乐观成交。
- 做 action support 报告：每个被选择动作距行为数据有多远；分布外率超过门槛则降级 HOLD。
- 多标的训练必须报告逐标的结果；总体收益不能掩盖多数标的退化。

### 5.4 生产闸门

- 全阶段 `RESEARCH_ONLY` 起步；shadow 不发送 RL 提醒，不能写入 approved strategy cache。
- 模型注册包含 model/feature/reward/action-space/data/simulator/code 版本及哈希，版本任一变化都重新验收。
- 在线检查缺特征、漂移、低置信、mask 后只剩 HOLD、推理超时或版本不匹配时，一律 fail-closed 到确定性策略或 HOLD。
- RL 永远不拥有交易 API；通过 shadow 后也只是提议。Wheel 硬风控、LLM fail-closed 审核和 Telegram 人工决定继续保留。
- 人工确认不是 reward 真值；真实成交与最终结果必须独立留痕，在线数据只能经版本化离线批次进入下一模型，禁止在线自学习。

## 结论建议（5 行）
不建议直接深度 RL：当前事件数据与模拟器均未过闸门，无法证明可靠性。
建议 ES 先行：先交付可解释基线，并补齐轨迹、成交、事件回测和样本外数据面。
同时采用混合预研：用规则/多组 ES 轨迹做行为克隆与候选排序，只标 `RESEARCH_ONLY`。
事件数据解锁后再做保守离线 RL，经过预注册测试与长期 shadow 才可替换战术提议。
最终链条保持 `RL 提议 → Wheel 硬风控 → LLM 审核 → 人工决定`，永久无自动下单。
