# 回测 CLI / 参数寻优 / 策略级 RL 产品评估（sol，2026-08-13）

## 结论与适用边界

方向成立，但当前草案不宜原样进入编码。必须先冻结参数契约、成交尝试口径、报告 schema 和训练/验证数据边界，再实现优化器。阶段 1 应对外称“进化策略参数寻优（ES）”，不要称为策略级强化学习；阶段 2 才是会根据状态选择动作的 RL。所有回测与训练产物在历史事件数据覆盖不足期间保持 `RESEARCH_ONLY`，不得写成可执行收益承诺，也不得绕过 Wheel 硬风控、LLM 审核和人工确认。

另有一处现有产品契约冲突必须在 S1 前裁决：`doc/BACKTEST.md` 和 `doc/WHEEL_STRATEGY.md` 当前明确规定价格锚点、最大库存不参与优化，而草案把 `price_low`、`price_high`、`max_inventory` 放入 ES 搜索空间。老板“后续替代人工指定参数”的新指令可以改变旧边界，但需要任务记录明确覆盖关系；在没有明确裁决前，阶段 1 默认只优化战术参数，战略参数仅允许人工给定窄范围并由人批准结果。

## 1. 参数命名与契约核对

### 1.1 推荐最终文案

| 建议中文文案 | 建议 JSON 键 | 单位/约束 | 对草案的调整 |
| --- | --- | --- | --- |
| 满仓价格 | `full_position_price` | 标的交易币种/股；`> 0` | “满仓价”可用，但键 `price_low` 只表达高低、不表达业务结果 |
| 清仓价格 | `zero_position_price` | 同币种/股；`> 满仓价格` | “清仓价”可用；键 `price_high` 同样语义不足 |
| 最大持股数 | `max_inventory` | 股，正整数 | 比“最大库存”更适合普通用户；内部仍可称库存 |
| 再次出手价差 | `move_interval_pct` | 百分比，明确按“距上次有效成交时标的价”的绝对变动计算 | “出手间隔”容易被理解成时间；原语义还缺基准价、方向和未成交后是否重置 |
| 最低每股权利金 | `min_premium_per_share` | 标的交易币种/股，`>= 0` | 必须说明每股还是每张合约、按 Bid/限价/成交价哪一种判断；“低于不买”与 Wheel 只卖期权冲突，应写“低于不卖” |
| 正股切换阈值 | `stock_switch_pct` | 百分比；触发后只产生正股建议，仍经审核和人工确认 | “正股直换线”不够自然；必须定义相对哪个价格、Put/Call 两侧是否对称 |
| 免交易库存差 | `trade_gap` | 股，`>= 0` | “出手间隙”仍像时间；明确 `abs(目标持股数-有效持股数) <= 值` 时 HOLD |
| 最低期权质量分 | `min_option_quality` | `[0,1]` | `quality` 太泛，无法判断是观测分还是门槛，不建议缩短 |
| 最短到期天数 | `min_dte` | 自然日，当前 5–10 | “最快行权”不准确：美式期权可能提前行权，DTE 表示到期而非行权 |
| 最长到期天数 | `max_dte` | 自然日，且 `>= min_dte` | “最晚行权”同上 |
| 策略状态 | `strategic_state` | 枚举 | UI/报告显示“正常 / 谨慎 / 暂停增仓 / 退出”，JSON 枚举继续用稳定机器值 |

产品展示名应全中文；JSON 键建议使用上表稳定、通俗的英文 `snake_case`，不要使用中文 Unicode 键。这样既满足“后端 JSON 键同步改”的重命名要求，也不牺牲 CLI、数据库、第三方工具和日志的可操作性。若老板的原意是 JSON 键也必须用中文，S1 必须先单独确认，因为这会显著扩大兼容面。

### 1.2 每标的独立与存量兼容

- 每个参数集必须绑定 `symbol + market + currency + strategy_config_version`；训练范围、最优结果和报告不可跨标的复用或只按简称缓存。
- 报告中的价格和权利金必须带币种，持股/库存参数带“股”，DTE 带“自然日”，百分比字段不可接受 `0.05`/`5` 两种含义。
- `full_position_price < zero_position_price`，区间外目标持股数钳制；`max_inventory`、`trade_gap` 应为该标的有效股数口径，并与合约乘数换算分离。
- 旧 `price_position_curve` 多于两点时只取端点是有损迁移，不能称“自动等价迁移”。建议保留原 JSON 审计值，生成新版本并标记 `migration_lossy=true`；保存前在 CLI/运维迁移报告列出受影响标的。
- 新读旧、只写新；旧限额键和 `lot_size` 可忽略但须留下迁移告警/计数，不建议永久“静默”到无法对账。兼容期和移除版本应写入 API 文档。
- “取消每日出手上限”只取消配置和策略拒绝条件，不取消报告中的每日提醒/成交次数统计，也不改变 LLM 审核与人工逐单决定。

## 2. RL 风格训练报告结构

报告必须由版本化结构数据渲染，JSON 是单一事实源，HTML 和 Discord 只做确定性投影。建议 `schema_version` 起步即纳入，并区分 `generation_count`、`population_size` 和 `evaluation_count`；草案把“迭代次数”同时解释为总回测次数，容易误读。

### 2.1 顶部摘要

- 身份：报告 ID、生成时间、标的/市场/币种、策略配置版本、代码版本、数据区间、训练/验证/测试窗口、数据能力状态。
- 训练：算法名（ES）、代数、种群规模、总评估次数、seed 列表、停止原因、耗时。
- 结果：样本外最优净收益额/收益率、基线收益及超额、最大回撤、尝试成交数、成交数、未成交数、未成交率；明确费用、滑点、税费、指派模型是否已计入。
- 风险提示：`RESEARCH_ONLY` / `DATA_BLOCKED`、历史覆盖率、缺失字段、是否仅为 bar-time replay。Discord 摘要也必须带状态，不只展示收益。

### 2.2 每代训练轨迹

每代至少记录：`generation`、累计评估次数、当代训练集最优/均值/中位数/标准差、历史最优、验证集最优、最大回撤、未成交率、有效交易次数、参数种群离散度、变异尺度、耗时。收益应同时给金额和百分比，不用单独的总收益掩盖资本规模差异。

收敛图至少画“训练集当代最优、验证集最优、基线”三条线；未成交率和最大回撤使用独立图，不应与收益共用尺度。报告另列最终候选前 3–5 组，而非只给单点冠军，并给多 seed 的中位数、P10/P90 或置信区间与参数稳定区间。

### 2.3 结果与审计明细

- 最优参数：中文展示名、机器键、值、单位、搜索边界、是否撞边界、相对基线变化。
- 收益风险：毛/净权利金、总收益率、年化口径（数据足够时）、最大回撤、波动、最差窗口、Put 指派率、Call 行权机会成本、库存偏差、最大库存违规数。
- 执行质量：提醒数、成交尝试数、成交数、未成交数、`unfilled_ratio = 未成交数 / 成交尝试数`、按流动性分桶的未成交率；`HOLD`、`DATA_BLOCKED` 和无候选不能进入分母。
- 稳健性：训练/验证/测试分窗表现、不同 seed、费用/滑点/成交概率敏感性、与当前人工参数和 buy-and-hold/固定参数基线的比较。
- 可复现：输入数据快照 ID/哈希、代码版本、完整 CLI 参数（脱敏）、seed、搜索空间、奖励函数版本、模板版本、JSON/HTML 产物校验值。

### 2.4 移动端和 Discord

iPhone 16 Pro Max 以 430 CSS px 宽视口验收，同时覆盖 390 px，不能把桌面宽表缩小。首屏只放状态、样本外收益、回撤、未成交率和停止原因；参数与逐代明细使用卡片/折叠区，图表可横向缩放但正文不得横向滚动。Discord 只推 5–7 个核心字段和报告链接/附件，字段超限时不截断关键风险状态。

## 3. 阶段 1 进化策略设计评审

### 3.1 定位与搜索空间

简单 ES 适合作为零依赖、可复现的第一版黑盒寻优，但它不是“观察状态后学习动作”的策略级 RL。当前 10 个维度以 `20 代 × 8 个体` 搜索偏弱，且价格上下限、最大库存会改变战略风险，不能与战术参数无条件同权搜索。

建议分层：

1. 默认搜索战术参数：再次出手价差、最低每股权利金、正股切换阈值、免交易库存差、最低期权质量分、最短/最长 DTE。
2. 满仓/清仓价格和最大持股数由人给定，或只在人工批准的窄范围内搜索；输出仍是“候选配置”，不得自动覆盖生效配置。
3. 用约束参数化避免无效个体：先采样满仓价格，再采样正的区间宽度；先采样最短 DTE，再采样非负跨度；离散整数独立变异，不能对所有维度直接加同一个高斯噪声。
4. 每标的按自身价格、合约乘数和历史分位数定义范围；禁止把 00883 的绝对价格/库存范围复制给 09988。

### 3.2 建议的首版超参数

- 种群：10 维时建议 16–24 个体，首版默认 20；保留精英 20%（至少 4 个），并保留约 10% 随机移民防止过早收敛。
- 代数：默认最多 30–50 代，以总回测预算和超时控制；CLI 必须允许显式设置，并在启动前输出预计评估次数。
- 变异：连续变量先归一化到 `[0,1]`，初始标准差取各自搜索宽度的 10%–15%，随停滞自适应扩大、随稳定改进衰减，最小保持 2%–3%；整数 DTE/股数采用离散步长。
- 父代选择：按验证适应度排序的截断选择，保留全局冠军；相同 seed 必须得到相同轨迹。
- 早停：验证集最佳分数连续 8–10 代相对改善低于预设阈值（建议同时用绝对和相对阈值）才停止；若种群多样性过低则先重启部分个体，不直接宣称收敛。
- 多次运行：开发验收可固定单 seed；产品报告至少 5 个成交随机 seed，最终候选再用独立测试窗和更多 seed 复评。训练 seed 与测试 seed 不得相同。

这些是第一版默认值而非业务真理，需通过运行时预算基准后调整。若单次回测昂贵，可先缩小搜索维度，不能靠 8 个体覆盖 10 维后宣称已找到最优。

### 3.3 奖励函数

不能只用总收益：它偏好更长区间、更大资本和尾部风险，也容易对单一路径过拟合。建议以样本外、扣除费用后的收益率为主项：

`score = 净收益率 - λdd × 最大回撤 - λtail × 尾部损失 - λturnover × 成交成本`

最大库存违规、裸 Call、资金不足、未来数据泄漏等应是硬失败，不是可用收益抵消的软惩罚。未成交已通过“没有产生该笔收益”进入净收益，再加很重的未成交惩罚会重复计罚，并驱使模型选择零尝试。若业务确需流动性偏好，只加小权重且设置最低有效尝试数，同时把未成交率单独展示。各项必须无量纲归一化、版本化并在报告公开权重；首版先跑权重敏感性分析，再冻结默认值。

选择候选时以验证集为准，最终测试集只能使用一次。至少采用时间顺序的训练/验证/测试或 walk-forward，不能随机打散时序；报告同时展示当前人工参数基线，最优结果若不能在多个窗口/seed 稳定胜出，应输出“无可推荐参数”。

### 3.4 主要风险与闸门

- 历史完整事件数据当前仍 `DATA_BLOCKED`；在 bar-time 机械结算上训练出的“最优”只能用于研究。
- 优化器会利用模拟器缺陷（成交概率、收盘结算、费用、指派缺口）；必须做敏感性和样本外复评。
- 参数撞搜索边界通常表示范围不合理，不代表最佳值；报告需显式标记。
- 单标的高维搜索易过拟合；优先减少自由度并输出稳定平台，而非精确单点。
- 缓存写入不等于配置发布。只有通过数据闸门、样本外门槛和人工批准的版本才能被标成 `APPROVED_CANDIDATE`。

## 4. 未成交概率模型评审

现有 `QualityScore` 中 `spread = clamp01(1 - 相对买卖价差)`，因此草案的 `1-spread` 确实表示“宽价差失败分量”，方向正确；`100/(volume+100)` 和 `1000/(OI+1000)` 也都是流动性越差、失败分越高。但三项等权和固定 100/1000 拐点没有成交回填数据支撑，只能作为启发式，不能描述为真实概率。

建议首版：

- 明确订单假设（卖出 Put/Call、限价位置、有效时长）。若机械按 Bid 卖出，通常与挂中间价的未成交概率不是同一模型；不定义限价就无法解释概率。
- 暂定失败分权重为相对价差 0.55、近期成交量 0.30、OI 0.15。OI 更像市场深度/活跃度代理，对本次是否成交的即时解释力较弱；该权重只作待校准默认值。
- 成交量/OI 的缩放应按市场、标的、期权类型和 DTE 分桶，用历史分位数或 `log1p` 标准化；至少允许配置版本，避免港股与美股共用绝对阈值。
- 加入可得时的盘口深度、报价新鲜度、相对限价位置和交易时段；在数据未具备前不得伪造这些字段。
- `p_fail` 应有合理上下限（例如避免启发式给出绝对 0/1），并标记 `model_kind=heuristic`、`model_version` 和各分量。未来以真实订单尝试/成交回填做可靠性曲线、Brier score 和分桶校准后再升级。
- 随机数按 `run_seed + symbol + bar_ts + contract + attempt_index` 派生，使新增无关候选不改变已有订单结果；报告用多 seed 分布，单 seed 仅用于复现。
- 只对真正发出成交尝试的期权动作抽样。正股建议、HOLD、DATA_BLOCKED、候选淘汰不进入未成交分母；分母为零时返回 `null/not_applicable`，不能报 0%。

指标命名建议保留一个事实字段 `unfilled_ratio`，`fill_rate` 可由成交数/尝试数推导，但两者都要同时输出计数，防止舍入和口径不一致。还应区分“模拟未成交”和“人工未执行”；两者原因完全不同。

## 5. 切片粒度与执行顺序

六个主题覆盖完整，但 S1（后端契约、迁移、全部前端和文档）与 S4（数据 schema、HTML、Discord）过大，且报告 schema 晚于优化器会导致 S3 自行发明轨迹结构。建议拆成 8 片：

| 顺序 | 建议切片 | 独立验收产物 |
| --- | --- | --- |
| 0 | 契约裁决与数据闸门 | 参数字典、旧/新映射、有损迁移名单、战略参数是否可优化、尝试/成交口径、报告 JSON schema；无代码也必须先签字 |
| 1 | 参数后端与兼容迁移 | 新读旧/只写新、每标的版本、删日上限领域逻辑、契约/实库迁移测试 |
| 2 | 参数消费端中文化 | 保留的 watchlist 配置入口、CLI 帮助、LLM 审核文本、报告字段和文档一致；不再建设待删除 results 页 |
| 3 | 未成交模拟与基础指标 | 订单假设、模型版本、稳定派生 seed、计数口径、多流动性等级测试 |
| 4 | 标准报告数据面与基础 CLI | 先让单次回测输出版本化 JSON/HTML；430/390 px 验收，尚不接 Discord |
| 5 | ES 参数寻优 | 搜索、约束、walk-forward、多 seed、早停、轨迹严格复用 S4 schema |
| 6 | 缓存与 LLM 上下文 | 带 symbol/config/data/model 版本及状态的缓存；过期和不合格缓存不注入 |
| 7 | Discord 推送与 Web 退役 | 幂等推送、失败可重试、真实 channel smoke；确认 CLI/报告功能等价后删 results 导航/页面 |

若组织上必须坚持 6 片，最低调整为：S1 只做契约/后端兼容；中文消费端并入 Web 退役，S2 未成交；S3 改为“报告 JSON schema + ES”；S4 只做 HTML/Discord；S5 缓存/LLM；S6 Web。依赖顺序必须是 `契约 → 未成交/指标 → 报告 schema → ES → 缓存/LLM → 推送与 Web 退役`。Web 删除可并行开发，但上线不得早于 CLI、HTML、Discord 查阅链路验收通过。

端到端命令还需避免一个操作风险：`-cache` 和 `-push` 是外部副作用，不应与默认训练隐式绑定。建议先生成带 report ID 的不可变产物，再用显式子命令/确认参数发布缓存和推送；重复执行同一 report ID 必须幂等。

## 6. 阶段 2 策略级 RL 与 LLM 动态策略边界

### 6.1 清晰分工

- **策略级 RL**：只消费可审计、数值化的市场/库存/期权快照，在离散且受 action mask 限制的动作空间中给出 `HOLD / 卖 Put 候选 / 卖 Call 候选 / 正股调整候选`、数量建议和置信度。目标是学习出手时机与候选排序，不负责解释新闻、修改硬风控或直接下单。
- **Wheel 领域层**：永久拥有数据完整性、现金担保、备兑、最大持股数、状态、DTE、禁止裸仓等硬约束。RL 和 LLM 都不能覆盖。
- **LLM 动态策略**：读取结构化的近期回测摘要、RL 建议、当前快照和适用状态，做上下文审核、异常识别和人类可读理由；可以批准、拒绝或降级为 HOLD，不应把自然语言变成未经验证的新参数，也不应凭主观判断抬高 RL 数量。
- **人工**：在 Discord/Telegram 查看标准报告和理由，决定是否采用候选配置、是否对单次提醒下单。参数发布与每笔交易都保留版本和审计。

推荐协作链路为：`可信快照 → RL/确定性策略提出候选 → Wheel 硬约束过滤 → LLM fail-closed 审核 → Discord/Telegram 人工决定`。上线早期使用 shadow mode：RL 与现有确定性策略并行给建议但不驱动提醒，比较样本外收益、回撤、未成交率、违规率和动作一致性；通过门槛后才逐步替换战术选择。

### 6.2 缓存契约

策略缓存不能只有“最优参数+收益”。至少应包含 `symbol/market/currency`、策略与配置版本、训练数据窗口/哈希、算法与奖励版本、成交模型版本、seed 集、训练/验证/测试指标、置信区间、能力状态、生成/过期时间和批准状态。LLM 只接收压缩后的确定性摘要及报告引用，不能注入全部逐代轨迹挤占上下文。

LLM 可把市场事件等非结构化信息作为“拒绝/请求复核”依据，但在这些特征没有被可复现地写入训练状态前，不能把 LLM 临时判断回灌为 RL 的真值标签。反过来，RL 的高分也不是 LLM 必须批准的理由。两者冲突时默认 HOLD，并记录 RL 动作、硬约束结果、LLM 结论和人工动作，形成未来离线评估数据，而不是在线自动自学习。

阶段 2 的奖励应基于真实的延迟收益、风险和执行反馈；人工是否点击不等同于动作好坏，不能直接作为唯一 reward。首版坚持离线训练、版本化发布、可回滚、无自动下单；在线探索和自动参数更新继续 `OUT_OF_SCOPE`。

## 产品验收门槛

1. 任意报告能从 JSON 无 LLM 参与地重复渲染为一致 HTML，且关键汇总可由明细计数复算。
2. 同数据、参数、代码版本和 seed 得到相同轨迹；多 seed 报告展示分布而非单点好运。
3. 旧参数逐标的迁移可对账，有损曲线迁移显式列出；所有价格、股数、百分比和 DTE 单位无歧义。
4. 未成交率只统计成交尝试，且高流动性样例的预测未成交率低于低流动性样例；启发式状态清晰可见。
5. ES 只有在样本外、多窗口相对人工基线稳定改善且零硬约束违规时才输出候选，否则明确输出“无可推荐参数”。
6. 缓存、Discord 推送、参数发布均为显式、幂等、可审计动作；Web 退役前 CLI 和移动报告查阅链路已经验收。
