# 回测详情「重新运行」 (S-UI-rerun) — 2026-08-02

状态: ✅ 已合并 (PR #151, commit 8a3d5b6)

## 背景
AUTO_ADVANCE 根任务循环 ⑥ 老板长期目标(UI 打磨):回测迭代参数是
高频动作,但详情页看完结果后必须手抄代码/策略/参数到顶部表单。
补「看结果→调参→再跑」迭代闭环。

## 改动
1. **results.html**: detail-export 行(导出 CSV/JSON 旁)加「重新运行」
   button(`#rerun-btn`,分隔符「 · 」)。
2. **app.js**:
   - `let rerunHandler = null`(模块级);`renderDetail` 每次渲染调用
     `if (rerunHandler) rerunHandler(d)`——跨闭包桥接(initResultsPage
     持有 strategy 注册表)。
   - initResultsPage 注入 handler:点击 → 代码/策略/参数回填表单
     (`renderParamFields(st, d.params, "run-param-fields")` values 回填,
     与 watchlist 编辑同款),取消 watchlist 复选框,滚动到表单聚焦
     代码框。
   - 策略不在注册表(内部基准 buy-hold 等):保留代码,showError 提示
     手动选策略——select 无法回填不存在的 option。
3. 测试: TestRerunJS(9 断言 app.js + 2 断言 html)。

## 备注
- 验收小坑:首版直接在 select.value = d.strategy,未查注册表——本地库
  里 buy-hold(多 symbol 回测对照基准)不在 /v1/strategies,select 静默
  保持原值,提交会用错策略。验收脚本抓出后改为 strategyByName 守卫 +
  降级提示。教训:表单回填必须先验证值在选项集内。

  每次渲染重新绑定,避免详情切换后 handler 绑到旧 id。
